❷ Project Overview (Detailed)

🧠 Goal: Predict when to change a patient’s posture to prevent pressure ulcers.
📡 How: Use temperature sensors (DS18B20, DHT22) with ESP32 to collect data, send via MQTT to Firebase, and analyze with ML models.
📱 Interface: iOS app shows real-time posture status and alerts.

🗂 System Architecture

The system consists of 6 key components:

  • • IoT Device (ESP32): Collects skin temperature (DS18B20) and ambient humidity (DHT22)
  • • MQTT Broker (HiveMQ): Secure TLS transmission to cloud
  • • Firebase: Stores real-time sensor data and user metadata
  • • Backend (FastAPI): Handles model inference and account logic
  • • ML Engine: Predicts next posture change time using Random Forest
  • • LLM Analyzer: Summarizes daily conditions based on environmental logs

📌 Main Features

  1. Patient Dashboard
    Caregivers view a list of assigned patients, including:
    • • Personal info (e.g., age, ID, condition)
    • • Environmental data (recent temperatures/humidity)
  2. Next Posture Prediction
    When a posture change is manually tagged, the system predicts when the next change is needed.
  3. Daily Summary & Risk Alert
    At sleep mode entry, the app analyzes:
    • • Cumulative ambient data
    • • Posture change logs
    • • Risk level (based on inactivity or temperature anomalies)
    A push notification is sent in these cases:
    • • Patient is in danger (low mobility or poor condition)
    • • Predicted posture change time is approaching
    • • Daily summary is generated

🔍 Technical Details

▲ Overall System Architecture: From Sensor to ML/LLM Analysis


1. IoT Logic (ESP32 + MQTT)

- The ESP32 reads data every minute from DS18B20 and DHT22 sensors.
- The values are formatted as JSON and transmitted via TLS-secured MQTT to HiveMQ Cloud.
- Firebase Realtime Database is updated instantly for frontend binding.
- Power-efficient design allows deployment in long-term care settings.


2. Machine Learning (Random Forest)

- A Random Forest model is trained on labeled data where each entry contains:
{last posture change time, temperature delta, ambient humidity, sleep state}
- The model predicts the time interval until the next posture change.
- Inference is executed in the backend (FastAPI), triggered by a posture tagging event.


3. Daily Summary via LLM

- When the patient enters sleep mode, the system generates a prompt using that day's data:
“Summarize the patient's mobility and environment on June 14 based on…”
- The prompt includes:

  • • Temperature and humidity logs
  • • Posture change count and timings
- The LLM generates a natural-language summary (e.g., “The patient remained inactive for over 4 hours...”).
